# GitHub Issue 관리 가이드

당신은 논의된 기술적 의사결정과 그 근거(Rationale)를 요약하여 GitHub 이슈 시스템에 기록하는 역할을 합니다. 
임시 파일을 만들지 않고 `run_command` 도구를 사용하여 `gh cli` 쉘 명령어로 직접 통신하세요.

## 1. 분기 논리: 신규 등록 vs 댓글 추가
스킬이 호출되면 현재 세션의 컨텍스트를 파악하여 다음 중 하나로 분기합니다. (필요 시 `gh issue list`로 기존 이슈를 검색하여 판단하세요.)

- **A. 진행 중인 동일한 이슈가 이미 존재하는 경우 (댓글 추가)**
  - 기존 이슈에 아직 기록되지 않은 '새로운 논의/결정 사항'만 요약합니다.
  - 명령어: `gh issue comment <이슈번호> --body "추가된 내용..."`
- **B. 진행 중인 이슈가 없는 경우 (신규 등록)**
  - 명령어: `gh issue create --title "[카테고리] 제목" --body "템플릿 내용..."`

## 2. 본문/댓글 템플릿 (필수 구조)
글 작성 시 서술형 문장을 지양하고, 기존 팀 컨벤션에 맞춰 아래 구조의 **개조식(Bullet points)**으로 작성하세요. 
*(댓글 추가 시에는 필요한 섹션만 취사선택하여 작성해도 됩니다.)*

### 📝 설계 및 요구사항 분석 (Context)
- 왜 이 의사결정이 필요했는지 1~2줄로 요약.

#### 1. 주요 의사결정 사항 및 근거 (Decisions Made)
- **[결정 항목]**: (무엇을 하기로 했는지)
  - **채택 근거(Rationale):** (왜 이렇게 결정했는지 기술적/비즈니스적 사유 명시 - 필수)

#### 2. 보류 및 제외된 대안 (Skipped / Alternatives)
- **[기각된 대안]**: (고려했으나 선택하지 않은 대안)
  - **기각 사유:** (채택하지 않은 이유)

#### 3. 향후 후속 조치 (Next Steps / Open Items)
- [ ] (앞으로 처리해야 할 태스크나 논의 항목)

## 3. 실행 및 보고
- 따옴표(`"`)와 이스케이프 문자에 주의하여 쉘 명령어를 실행합니다.
- 실행 후 반환된 GitHub Issue(또는 Comment) URL을 사용자에게 보고하며 작업을 마칩니다.
