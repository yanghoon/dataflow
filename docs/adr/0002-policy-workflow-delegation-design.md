# ADR 0002: PolicyWorkflow의 명시적 위임 및 청크 기반 처리 설계

## Status
Accepted

## Context
기존의 정책 워크플로우(Policy Workflow)를 구현함에 있어 템플릿 메서드(Template Method) 패턴을 사용할 경우, 상위 클래스가 제어 흐름을 독점하게 되어 하위 클래스(구체적인 정책 구현체)에서 파라미터나 전체 흐름을 유연하게 제어하기 어려운 한계가 있었습니다. 
또한 대용량 데이터를 한 번에 조회하고 처리할 때 메모리 부족(OOM, OutOfMemory) 위험이 존재하며, 각 정책(예: 휴면 고객 처리 등)이 특정 도메인 로직이나 `EventId`에 강하게 결합되는 것을 방지하고 독립성을 보장해야 할 필요성이 대두되었습니다.

## Decision
이러한 문제를 해결하기 위해 다음 사항들을 결정했습니다:

1. **템플릿 메서드에서 명시적 위임(Explicit Delegation)으로 전환**
   - 상위 클래스가 흐름을 강제하는 대신, 하위 클래스가 공통 기능을 헬퍼 메서드(Helper Method) 형태로 명시적으로 호출하도록 변경합니다.
   - 이를 통해 하위 클래스가 제어 흐름과 파라미터를 직접 결정(Dictate)하게 되어 코드의 가시성(Visibility)과 유연성(Flexibility)이 크게 향상됩니다.

2. **`RowCallbackHandler` 및 청크(Chunk) 기반 처리 도입**
   - 대규모 데이터 처리 시 발생하는 OOM 위험을 완화하기 위해 `RowCallbackHandler`를 활용합니다.
   - 데이터를 메모리에 한 번에 올리지 않고, 500건 단위의 청크(Chunk)로 분할하여 안정적으로 스트리밍 및 처리합니다.

3. **엄격한 도메인 독립성 (Strict Domain Independence) 유지**
   - 각 정책(예: 휴면 고객 정책)은 자신만의 고유한 `EventId`를 내부적으로 캡슐화합니다.
   - 프로퍼티 추출 및 변환 로직 또한 각 정책 내에서 독자적으로 수행하도록 하여 도메인 간의 결합도를 최소화합니다.

## Consequences
- **장점 (Positive)**:
    - 정책별로 다양한 요구사항(파라미터 변경, 특정 단계 생략 등)을 수용하기 쉬워져 확장성이 높아집니다.
    - 메모리 사용량이 일정하게 유지되므로(500건 청크 단위) 대용량 배치 처리의 안정성이 확보됩니다.
    - 정책 추가 및 수정 시 다른 도메인에 미치는 영향이 최소화되어 유지보수가 용이해집니다.
- **단점/주의사항 (Negative)**:
    - 공통 로직(헬퍼 메서드)을 하위 클래스에서 직접 호출해야 하므로, 개발자 실수로 필수 호출이 누락되지 않도록 주의가 필요합니다.
    - 하드코딩된 청크 사이즈(500건)가 향후 성능 튜닝 과정에서 병목이 될 경우, 이를 동적으로 설정할 수 있도록 개선해야 할 수 있습니다.
